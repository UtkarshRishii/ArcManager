Product Name

ArcManager
Personal Client Payment & Finance Manager

You can rename it later to whatever you want.

Product Goal

Build a secure personal finance-management application for tracking money received from clients, outstanding/pending payments, recurring payments, project-wise billing, payment schedules, and which personal bank account received each transaction.

The app is not a banking application and should not attempt to directly move money. It is a private bookkeeping/receivables-management system.

28. Critical Calculation Logic

Don't store calculated values like:

pending_amount
total_received
monthly_revenue

as manually editable values.

Calculate them from transactions.

Received
SUM(successful payments)
Project pending
project.total_amount
-
SUM(received payments for project)
Schedule remaining
schedule.amount
-
SUM(payments linked to schedule)
Overdue
due_date < current_date
AND remaining_amount > 0

This prevents the classic finance-app nightmare where the dashboard says ₹40k pending while the client page says ₹35k. 💀

==================================================
CRITICAL FINANCIAL LOGIC
==================================================

NEVER manually store calculated totals such as:

pending_amount
total_received
monthly_revenue

unless there is a very strong technical reason.

Calculate them from payment records.

Received:

SUM(successful payments)

Project pending:

project.total_amount - SUM(successful payments belonging to project)

Schedule remaining:

schedule.amount - SUM(successful payments linked to schedule)

Overdue:

due_date < current date
AND remaining amount > 0

Make all calculations centralized in the domain layer or database views/functions.

Avoid duplicated financial logic.

Use NUMERIC/BigDecimal for money.

NEVER use Float or Double for financial calculations.

35. One architectural change I'd make before you actually build it

Bro, don't make the bank-account section imply that the app is reading your bank account.

There are two completely different things:

V1 — Payment tracking

"₹10,000 received in HDFC ••••4821"

This is something you manually record.

V2 — Actual bank integration

"₹10,000 automatically detected from HDFC"

That requires a legitimate banking/open-banking integration and a much bigger security/compliance surface.

For your first version, manual recording + excellent ledger is the right move.
